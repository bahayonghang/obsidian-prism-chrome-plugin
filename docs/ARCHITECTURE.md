# Browser extension architecture

Modified 2026-11-24 for the independent Obsidian Prism Web community port. GPL-3.0-only.

## Execution boundaries

| Component | Responsibility | Boundary |
|---|---|---|
| `src/config-schema.js` | Defaults, validation, presets, language strings, browser storage abstraction, root theme/reading attributes including `formulaPreview` / `data-op-formula-preview` (adopting prior Prism root flags/style across isolated-world reloads without treating them as host originals), and decoupled settings UI theme resolvers (`uiThemeMode`, `resolveUiScheme`, `resolveUiPalette` falling back from `host` Native Palette to `obsidian`/`crystal`, and `applyUiThemeToRoot`) | Ordinary preferences only; secrets excluded from exports and page mirrors; `uiThemeMode` never affects Host Surface `resolveScheme`, `resolvePalette`, or `applyConfigToRoot` |
| `src/early-boot.js` | Start loading preferences at `document_start` and apply the initial visual state | Extension storage is asynchronous; do not claim guaranteed zero flash |
| `vendor/temml/temml.js`, `vendor/temml/temml-local.css` | Pinned offline Temml v0.14.0 LaTeX-to-MathML Core renderer and flattened MathML layout styles scoped strictly under `html[data-op-enabled="true"] .op-formula-preview` without `@font-face` or `.woff2` files | Static MIT-licensed vendor asset (`check.mjs` blocks `eval`, `new Function`, `innerHTML`, `document.write`, webfonts, and unscoped rules); uses OS native math fonts with zero `web_accessible_resources` |
| `src/formula.js` | LaTeX code-block detector (`isLikelyLatex`), `%` comment-line segmentation (`segmentLatex`), and MathML Core preview builder (`renderFormulaPreview`) with per-segment monospace fallback | Pure offline DOM-API module (`trust: false`, `throwOnError: true`); zero `innerHTML` or host `<pre><code>` mutation |
| `src/adapters.js` | Identify supported host elements (including de-nesting Gemini double-nested `<code-block>` Code Surfaces, owning `codeSurfaceFor` / `codeHeaderFor` / `codeWellFor` resolution, and filtering owned/nested `<pre>` nodes from `codeBlocks()`), extract loaded conversation structure, declare per-site layout facts (width-limiter `contentWidth.targets`, `contentWidth.userTurnTargets`, and `composerTargets`, native reading widths, composer card/grid slots, prioritized primary actions), detect overlaid docks, and compute dock collision avoidance + edge margins | DOM selectors, read-only geometry queries, and declarations only; no internal ChatGPT/Gemini API calls |
| `src/content.js` | Singleton instance handover (`data-op-instance`), reversible reading tools (including `syncFormulas()` Formula Preview lifecycle and reversible `data-op-code-icon-fill` / `data-op-code-icon-stroke` header marks), width quick toggle, zero-polling dock avoidance/popover placement, effects and optional manual-translation controls | Isolated content script; preserve host message/editor ownership |
| `src/background.js` | Serialized settings writes (`OP_CONFIG_PATCH` for extension pages, constrained `OP_CONTENT_WIDTH_SET` for top-frame chat pages), optional translation requests and credential access | Validate senders, enums, origins and endpoint settings; do not expose general config patches to chat pages or a general URL-fetch proxy |
| `popup/*` | Settings popup and options page (including Reading tab `formulaPreview` toggle, decoupled `#btn-ui-theme` / `#cfg-uiThemeMode` controls, `color-scheme` + light pre-load fallback, and non-destructive palette-card click preview via `previewSchemeOverride`) | Packaged scripts, no inline executable handlers or remote code |
| `styles/*` | Palette variables (including `color-scheme: dark` / `color-scheme: light` on Native Palette `host` rules), host-specific styling (Code Surface de-nesting, Native Math Surface theme/overflow fallback, Formula Preview cards, User Turn & Composer width uncap rules) and extension-owned controls | Scope overrides under enabled extension attributes |

Content scripts run only on the three explicitly supported HTTPS origins and only in the top-level document. The extension does not declare external messaging or public web-accessible resources.

## Browser manifests

`manifest.json` is the Chrome manifest. `manifests/firefox.json` is a complete Firefox variant; the build copies it to `dist/firefox/manifest.json`. Runtime files are shared.

Chrome uses `background.service_worker`; Firefox uses `background.scripts` with the configuration module loaded before the background module. Both use Manifest V3, request `storage`, and include only the ChatGPT/Gemini host permissions by default.

The optional host declarations allow user-selected HTTPS translation services and explicit HTTP loopback endpoints. Actual browser permission is requested for the configured scheme and hostname; match patterns do not isolate ports. Runtime requests retain the exact configured endpoint, including port and path. Firefox additionally declares optional data-transmission types, while core functionality declares `required: ["none"]`.

Official references:

- [Background compatibility](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/background)
- [Firefox data collection consent](https://extensionworkshop.com/documentation/develop/firefox-builtin-data-consent/)
- [Chrome cross-origin extension requests](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)
- [Extension storage versus page storage](https://developer.chrome.com/docs/extensions/develop/concepts/storage-and-cookies)

## Appearance and lifecycle

Theme variables are supplied at `document_start`; stored preferences then determine which scoped overrides activate. Disabling the extension for a site removes its root flags, owned controls, temporary styles and active effects. The host retains its original classes and content.

The settings popup and options page manage their own independent `uiThemeMode` (`auto`, `light`, `dark`, defaulting to `auto`) via `resolveUiScheme`, `resolveUiPalette`, and `applyUiThemeToRoot`: the settings chrome remains themed even when `enabled` is `false`, falls back from Native Palette (`host`) to `obsidian` (dark) or `crystal` (light) for legibility while `#chat-preview` continues reflecting Host Surface settings (`themeMode`, `palette`, `lightPreset`), and pairs document-level `color-scheme: light dark` + `@media (prefers-color-scheme: light)` pre-load fallback variables in `popup/popup.css` with explicit `color-scheme` rules on both `html[data-op-scheme]` and Native Palette (`host`) surfaces in `styles/prism-tokens.css`. Clicking a palette card previews that card's scheme (`previewSchemeOverride`) and updates only that group's palette preset without mutating `themeMode` (including already-selected defaults).

Site changes are detected by bounded, coalesced DOM work. A webpage is not a stable API: when a target cannot be identified, skip the enhancement instead of rewriting arbitrary DOM. Route changes, regenerated responses, streamed code and replaced composers must be treated as normal lifecycle events.

Stream highlights are a progressive enhancement using `CSS.highlights`. They must not wrap or rewrite host text nodes. Reduced-motion users receive the static presentation. Animation work should cease when effects are disabled or the page is hidden; this is a statement about the extension's own work, not total site CPU/GPU usage.

## Reading and estimation

The outline derives from recognized user turns already loaded in the DOM. It does not fetch missing history. Keyboard navigation yields to text entry and modal interactions. Code folding is manual and reversible; copied code remains the original host text.

For Code Surfaces and Native Math Surfaces (`#33`), `Adapters.findCodeSurfaces` resolves Gemini's double-nested `<code-block>` wrapper by selecting only the inner `.code-block` card, while `styles/hosts.css` resets outer `code-block:has(.code-block)` to a borderless block container, clears inner `overflow: hidden` clipping around sticky headers, and aligns card radii—eliminating stray border slivers and double framing. `syncSurfaces()` pairs Material/icon-font CSS variable overrides (`--mat-icon-color`, `--mdc-icon-button-icon-color`) with reversible `data-op-code-icon-fill` and `data-op-code-icon-stroke` marks computed from SVG element `getComputedStyle` paint (respecting `:not([fill="none"])` / `:not([stroke="none"])`) to preserve >= 4.5:1 header icon contrast across all four optical palettes. Outside Native Palette (`:not([data-op-effective-palette="host"])`), `styles/hosts.css` also guards Native Math Surface containers (`.math-block`, `.math-inline`, `.katex*`, `mjx-container`, excluding `[data-op-owned]` and `pre`) by enforcing `--op-fg` contrast, clearing background slabs, and enabling internal horizontal scrolling (`overflow-x: auto`, `min-width: 0`, `max-width: 100%`) on wide display equations without breaking reading-column bounds.

Formula Preview (`#34`–`#35`, [ADR-0003](adr/0003-local-mathml-formula-preview.md)) runs offline inside `document_idle` using pinned `vendor/temml/temml.js` (v0.14.0), `vendor/temml/temml-local.css`, and `src/formula.js`. When `formulaPreview` is enabled (default `true`, synced via `data-op-formula-preview`), `syncFormulas()` (executing immediately before `syncCodes()`) detects qualifying LaTeX blocks across ChatGPT and Gemini (`isLikelyLatex` with explicit math tags or math heuristics plus programming-language negative guards), segments multi-equation blocks at depth-zero blank or `%` comment lines, and renders native MathML Core into `.op-formula-preview[data-op-owned]`. Individual failing segments degrade gracefully to monospace `.op-formula-fallback` (excluded from `adapter.codeBlocks()`), while all-invalid blocks remain untouched as native Code Surfaces. Host `<pre><code>` elements are never rewritten or reparented, preserving lossless native Copy; source containers hide reversibly via `data-op-formula-source-hidden="true"` (`display: none !important`, never setting `hidden` or `aria-hidden`, so Context Vial continues counting the untouched source code exactly once without double-counting the preview). A `.op-formula-toggle` button mounted in the code header (or a fallback `.op-formula-bar` paired with `data-op-formula-bare="true"` framing when headerless) toggles between Formula and Source views (`源码` / `公式`). Streaming blocks debounce re-renders by 280ms; active Formula views skip 48-line folding while preserving prior `savedFoldState` across Source/Formula switches; Native Palette (`host`) keeps Formula Preview active while inheriting host foreground colors (`color: inherit`); and toggling `formulaPreview: false`, disabling the extension, or `stop()` immediately cancels pending timers, removes all owned preview nodes and `data-op-formula-*` marks, and restores original Code Surfaces and any 48+ line fold bars.

The context display uses a documented local DOM heuristic (ADR-0001) rather than a model-specific tokenizer or internal account API. It strips non-content UI chrome, weights CJK, prose, and code separately, and excludes off-screen virtualized turns, hidden system prompts, and binary/document attachment bodies (marking visible attachments with `+` and listing the uncounted count). Its Reference Capacity defaults to `auto` (resolving from the visible model label, including the ChatGPT tier label: Pro / Thinking / High / xHigh map to `400K` and Instant to `128K`; per-host fallbacks are `1M` on Gemini and `128K` on ChatGPT, where an unrecognized label is flagged with `?` and a hint to set it in settings; a manual preset from `32K` to `2M` always wins). The resolver reports one `source` (`manual`, `matched`, `fallback` or `unrecognized`); only `unrecognized` shows the `?`. Product text must continue labeling the readout as a local estimate.

Pixel companions were removed in v0.2.0; the retired `mascot` setting is ignored. Ambient environments now use three CSS transform/opacity layers and optional fixed decorative glyph/grid textures. These are never derived from user content. The stage sits behind text inside an isolated recognized main surface and cannot receive pointer events. Bounds follow resize/scroll events, without permanent JavaScript polling. CSS motion pauses for hidden pages, disabled motion and reduced-motion preferences. A visible moving background still incurs rendering work.

Adapters also identify whole composer shells (plus `composerCardSurface` for outer card bounds such as Gemini `input-area-v2`), code surfaces/headers, column containers, model triggers, add triggers, chips, visible attachments, trailing spacers, and left navigation surfaces using explicit selectors before constrained semantic/geometry fallbacks. The runtime records original marker attribute values in `surfaceMarks`, restores them when a surface changes, when Native Palette (`host`) or `composerRestyle: false` is chosen, or when the extension is disabled, and reattaches owned layers after host replacement. Consistent with ADR-0002, the native editor, Model Capsule, attachments, and navigation nodes are styled strictly in place without reparenting or rewriting framework-owned text nodes. For the two-row prototype (`composerRestyle: true`), `composerGrid` verifies either the site's declared area names (`composerGridAreas`: ChatGPT `leading`/`primary`/`trailing`, Gemini `leading-actions`/`text-input`/`trailing-actions`) or positional structural slots (`data-op-composer-leading`/`-primary`/`-trailing`), marks the trailing flex toolbar (`data-op-composer-toolbar`) and the slot containing the Model Capsule (`data-op-model-capsule-item`), and ranks `composerPrimaryAction` by selector tier (`Send` > `Voice` > `Microphone` > trailing fallback). CSS overrides the verified grid into two columns (`auto minmax(0, 1fr)`) and places `data-op-model-capsule-item` immediately right of `+` via `order: -10` and `margin-inline-end: auto`, while `data-op-composer-attachment` styles attachment previews inside the card and `data-op-model-capsule::before` renders the four-pointed star.

From v0.4.0/v0.4.1, composer backdrops and `Composer Scrim` operate in dual mode via `Adapters.isComposerDockOverlaid(dock, scroller, view)` and per-host adapter capability flags (`usesOverlayScrim`, `usesScrollerAlphaFade`). In active conversations (never in Home State or Native Palette), the outermost recognized dock carries `data-op-composer-dock`, while all recognized backdrop layers (`data-op-composer-backdrop`) unconditionally clear native paint, gradients, masks, `box-shadow`, `--sharp-edge-*` shadow variables, non-scrim `::before`, and all `::after` layers across the bounded dock ancestor chain and adjacent disclaimer shells (strictly protecting the Composer Surface, attachments, dialogs, and menus). From v0.4.3 (#41) the ChatGPT adapter leads with the host footer markers (`threadFooters`: `[data-thread-scroll-footer="true"]`, `[data-thread-composer-backdrop="true"]`, and the layer inside the scroll container that wraps them, which is the marker itself when the host makes it the scroller's direct child) with no ancestor budget. Without markers the existing bounded ancestor walk (small-region / bottom-dock heuristics; zero-size `display: contents` wrappers do not count toward its 14-layer budget) is the fallback. A structural test (a marker, or an absolute/fixed child of a scroll container) is used only to leave a Home State footer native and to stop the Thread Footer from becoming the dock host; it does not recognize footers on its own. Such a Thread Footer is paint-only: it is never the dock host (no dock spacing or `z-index` rules), and in the Home State it is left native. On the live ChatGPT layout measured on 2026-11-24 this footer is a child of the conversation scroll container, so a scroller mask would also fade the composer; v0.4.3 therefore adds no body fade there, and scrolled prose passes beside the Composer Surface. On ChatGPT (`usesOverlayScrim: false`, `usesScrollerAlphaFade: true`), both in-flow and overlaid docks stay purely transparent (never receiving `data-op-composer-scrim` or painting any canvas veil or blur); overlaid docks receive `data-op-composer-overlaid` (`z-index: 6 !important` above sticky code headers at `z-index: 5`) and preserve `--op-dock-clearance` (`padding-bottom` on `[data-op-thread-column]` or external `[data-op-thread-scroller]::after`), while independent message scrollers (`Adapters.isIndependentMessageScroller`, excluding sticky-in-scroller layouts that contain the dock or composer) receive a reversible Alpha-channel bottom `mask-image` via `data-op-scroller-fade` (`--op-scroller-fade-start` / `--op-scroller-fade-end`, defaulting to 24px/0px in flow) so scrolled prose softens without tinting the Ambient Stage or dimming the Composer Surface. On Gemini (`usesOverlayScrim: true`, `usesScrollerAlphaFade: false`), overlaid docks (`data-op-composer-overlaid`) receive `data-op-composer-scrim`: `::before` paints 44% `--op-canvas` in dark mode (26% in light mode) with `backdrop-filter: blur(14px)` and a `--op-scrim-feather: 16px` top mask feather—falling back without `backdrop-filter` support to a 56% dark / 36% light gradient (`32%`/`20%` at `16px`) with `mask-image: none`—and `data-op-thread-scroller` writes the measured overlap plus an 8px gap to `--op-dock-clearance` (`::after` spacer). Under `composerRestyle: true` (`data-op-composer="true"`), empty grid header rows (`data-op-composer-header-empty`), trailing empty/hidden-content shells inside the dock and up to 2 ancestor levels outside (`data-op-composer-empty-sibling`, including `flex: 0 0 0`), and inner/external disclaimers (`data-op-composer-disclaimer`, `view-transition-name`/negative-margin disclaimer shells, and Gemini `hallucination-disclaimer`) are collapsed or hidden while both active-conversation docks lower to a `5px` bottom padding (`4–6px` breathing margin); `composerRestyle: false`, Native Palette, Home State, or disabling restores native spacing cleanly without DOM reparenting. Selection flags on nested sidebar elements are normalized to one Active Highlight target per active item with `data-op-sidebar-active` (shape rules below). Native `aria-current`, `aria-selected` and `data-active` changes trigger the same coalesced lifecycle.

Bottom Dock lifecycle and geometry follow a zero-polling singleton contract: `src/content.js` stamps `data-op-instance` on `documentElement`, prunes any stale `[data-op-owned]` roots (`pruneOrphanRoots`), and yields silently via `disconnectRuntime()` / `yieldOwnership()` when superseded by a newer instance. On handover, the incoming runtime adopts existing `[attr="true"]` surface marks (`RUNTIME_SURFACE_ATTRS`) and `--op-reading-*` / `--op-dock-*` root variables (`RUNTIME_ROOT_VARS`) with zero visual flicker while preserving genuine non-`true` host attributes and non-runtime inline style declarations, so disabling, Native Palette, or `stop()` clears all runtime residue across both same-realm and isolated-world reloads. On scan, resize, and scroll events (never polling timers), `Adapters.findCornerFloatingObstacles`, `Adapters.dockEdgeMargin`, and `Adapters.computeDockAvoidance` shift `#op-bottom-dock` via `--op-dock-offset-x` and `--op-dock-offset-y` to remain clear of corner floating buttons, the Composer Surface, and the Conversation Rail within viewport margins, and `syncDockPopoverPosition()` flips (`data-op-popover-side="below"`) and shifts (`--op-vial-popover-shift-x`) the Context Vial popover cleanly inside the viewport.

The sidebar Active Highlight (`#42`) is chosen by `Adapters.sidebarActiveTargets(sidebars)`, which returns `{ element, shape }` per active item. When a host repeats its active state on a wrapper and its inner link (ChatGPT's `div[role="group"][aria-current="page"]` around `a[aria-current="page"]`), the outermost single-line row that carries the state, fits the row-height cap and holds exactly one link owns the highlight; a project group never passes its state to all of its rows. A near-square button without visible text is an `icon tile` (geometry decides; `data-uniform` only widens the tolerance), anything else is a `row`. The content script marks `data-op-sidebar-active` and, for tiles, `data-op-sidebar-active-tile`; both are runtime marks removed by Native Palette, sidebar style `native`, site or extension disable and `stop()`. `styles/hosts.css` draws a tile as a 16% accent fill with a 1px 34% accent inset ring, an accent icon and cleared host `::before`/`::after` overlays, and a row as one 11% accent layer with an `inset 2px 0 0` accent edge while descendants of the row paint no second layer. Light schemes deliberately deviate from the pure accent: the tile's icon ink, the row's 2px edge and the focus ring use `color-mix(in srgb, var(--op-accent) 75%, var(--op-fg))` (`--op-sidebar-active-ink`) so they keep at least 3:1 contrast; dark schemes use the accent itself. Active items keep their look on hover and draw an outline focus ring for `:focus-visible`.

## Content width

Content Width Presets (#21) change only the reading column. For `wide` and `full`, `content.js` measures the Primary Surface (main area) width and writes two root variables: `--op-reading-width` (the target paragraph width) and `--op-reading-shift` (a leftward shift so a full column clears the Conversation Rail). Like `--op-ambient-alpha`, their original inline value and priority are saved and restored, and an emptied `style` attribute that did not exist before is removed. `standard`, a disabled site and stop restore them, which returns the host's native width.

The widths use midpoint semantics: `full` is the main width minus a 20px left edge and a 56px rail reserve; `wide` is the midpoint of the site's native width and `full`, at most 1200px; below a 900px viewport both fall back to the main width minus 16px edges (`contentWidthTarget`). The native width is declared per site in `src/adapters.js` (`contentWidth.native`: ChatGPT 768px = 48rem, Gemini 708px), not measured at runtime.

`src/adapters.js` also declares the elements that actually limit the width (`contentWidth.targets`, `contentWidth.userTurnTargets`, and `contentWidth.composerTargets`) and owns those selectors. `styles/hosts.css` repeats them in host-scoped static rules, because CSS cannot read the adapter; `tests/content-width.test.cjs` is a static guard that fails when the two lists drift, or if any hardcoded `820px` ceiling or host-agnostic width rule enters the block. On ChatGPT, `main` bridges `--thread-content-max-width` to `--op-reading-width` and `--user-chat-width` to `min(100%, calc(var(--op-reading-width, 48rem) * 0.8))`; `#thread-bottom-container`, `#thread-bottom`, `#thread-bottom [class*="--thread-content-max-width"]`, and nested intermediate dock wrappers (`#thread-bottom :has(form[data-chatgpt-composer]):not(:has(> form[data-chatgpt-composer]))`) bridge `--thread-content-max-width` (uncapping nested dock shells at `max-width: 100%`); `[class*="transcriptContent"]`, `#thread-bottom :has(> form[data-chatgpt-composer])`, and `#thread-bottom > form[data-chatgpt-composer]` size and shift with `--op-reading-width` and `--op-reading-shift`; and `userTurnTargets` uncap outer/intermediate user-turn wrappers (`max-width: 100%`, bridging `--user-chat-width`) while sizing the User Turn bubble itself to `width: fit-content; max-width: min(100%, calc(var(--op-reading-width, 48rem) * 0.8)); margin-left: auto`. On Gemini, `chat-window` bridges both `--bard-chat-window-content-width-default` and `--bard-chat-window-content-width` to `--op-reading-width`; `user-query`, `.md-content > *`, `.response-footer`, and `hallucination-disclaimer` track `--op-reading-width` and `--op-reading-shift` (`user-query` also receives `width: 100%`); `userTurnTargets` uncap intermediate `user-query` wrappers (`width: 100%; max-width: 100%`) and inner `.query-text` / `.query-text-line` / `> *` containers (`max-width: 100%`) while sizing `.user-query-bubble-with-background` to `width: fit-content; max-width: min(100%, calc(var(--op-reading-width, 708px) * 0.8)); margin-left: auto`; and `composerTargets` uncap outer/inner input wrappers (`input-container :has(> .input-area-container)`, `.input-area-container :has(input-area-v2)`, `.input-area-container input-area-v2`) while `.input-area-container` tracks `var(--op-reading-width, 708px) - 48px` with `width: 100%` and `--op-reading-shift`. Thus User Turns scale proportionally (~80% of the reading column without any 820px ceiling or nested double-shrinking) while keeping short prompts compact and right-aligned, and the Composer Surface widens in lockstep with the reading column. The variables re-sync on every scan and on the existing `ResizeObserver` of the Primary Surface, with no extra observer or polling.

Width presets keep applying under Native Palette: Native Palette only leaves host colors untouched, and width is a layout preference, as in v0.3.0.

## Settings sizing

Toolbar popups negotiate their viewport from the content's intrinsic size. Their 440×600 document dimensions must not be capped by the initial popup viewport through `100vw`/`100vh`, otherwise a small initial viewport can keep the page collapsed. Both the header `#btn-ui-theme` button and the Appearance Details `#cfg-uiThemeMode` selector stay within that 440×600 layout with zero horizontal overflow in both `zh-CN` and `en-US`. The options document has its own early mode marker and remains viewport-responsive. Chromium CI calls `action.openPopup()` and inspects the resulting popup view without device-metric overrides; the tiny-iframe sizing regression is a separate cross-engine check, not an installed-extension claim.

## Optional translation

Only a user-requested, already visible thought block is eligible. Settings contain the endpoint and model; credentials are stored separately. A configuration export never includes credentials. Importing preferences must not enable transmission or grant permissions silently.

The background accepts a constrained translation operation, verifies its sender and the enabled site's configuration, builds the outgoing request from saved configuration, and applies limits and timeouts. It does not accept an arbitrary fetch URL or caller-provided authorization header. HTTPS is required except for explicit loopback hosts; redirects must not carry a key to another origin.

Translation responses are rendered as text, never executable markup. No automatic background translation, full-history upload, bundled free endpoint, or hidden-reasoning retrieval is part of this release.

## Builds and source provenance

The Python builder uses a fixed runtime/documentation allowlist. Each output is rooted at `manifest.json`, uses sorted entries with fixed timestamps and permissions, and receives a SHA-256 checksum. Nothing is discovered recursively from the working tree, so untracked credentials and development files cannot accidentally enter a package.

`npm run check` validates both manifests, packaged resources, Temml static security/scoping constraints (no `eval`/`new Function`/`innerHTML`, no webfonts or remote URLs, and all `vendor/temml/temml-local.css` selectors scoped under `html[data-op-enabled="true"] .op-formula-preview`), and runs JavaScript syntax checks. Node tests exercise behavior without paid services. Browser smoke tests use local fixtures; Chromium additionally loads the unpacked extension, while Firefox tests shared DOM behavior through injected runtime files. See [TESTING.md](TESTING.md) for the limits of that evidence.
